# CharBuild（角色配装 / 构筑）模块规格

> 类型：现状规格（as-is），不是新功能提案。
> 基线：2026-10-06 当前工作区，项目版本 1.4.5。
> 依据：源码、配置契约与现有测试。文中「支持」「返回」「保存」描述已实现行为。
> 只生成本地文档，不发布 issue，不修改业务代码。

## 问题陈述

《二重螺旋》玩家需要在角色、武器、魔之楔、协战、BUFF 与魔灵之间作配装选择，并在相同敌人、技能与输出过程下判断其效果。只看装备描述或单一面板数值，无法比较条件词条、武器精通、覆盖率与输出时长带来的差异。

CharBuild 已把这些能力分布在页面、配置模型、纯计算内核、Worker、云端构筑服务与 Agent 接口中，但缺少统一规格。维护者需要一份可追溯到当前实现的行为契约，用于理解模块边界、兼容历史存档、复用计算逻辑与组织回归验收。

## 解决方案

用户选定角色后，在同一份构筑中调整装备与战斗条件，查看角色与武器属性、伤害或目标函数值、装备收益、耐受与极化需求；可保存命名方案、切换 A/B/C 魔之楔配置、导入游戏装备或他人分享，并通过自动配装寻找更高目标值的候选方案。

单次伤害、复杂表达式与时间轴输出共用同一计算内核。简洁模式负责浏览，专业模式负责编辑，比较页负责多方案并排计算。云端服务保存公开构筑，程序化接口与 Agent 可在配置快照上操作，但不同入口的装配参数并不完全一致，不能默认得到相同结果。

### 领域术语

| 术语 | 本文口径 |
|---|---|
| 构筑 / CharBuild | 一个角色与其装备、加成、战斗条件组成的可计算实例 |
| 角色配置 / CharSettings | 用 ID、等级、数组与表达式保存的构筑设置，不保存计算类实例 |
| 魔之楔 / MOD | 装在角色、近战、远程或同律槽位的装备 |
| 中枢 / 光环 | 角色独立的魔之楔槽位，不占 8 个普通角色槽 |
| 同律武器 | 角色数据定义的技能武器，不是第三个可任意选购的武器槽 |
| MOD 变体 | 构筑内 A/B/C 三份魔之楔与中枢配置，不是三份完整构筑 |
| 命名方案 / Project | 按角色保存的完整设置快照，与 MOD 变体不同 |
| 基础动作 / baseName | 本次计算选中的角色技能、武器动作或时间轴 |
| 目标函数 | 用表达式指定比较与优化目标；不一定代表单次伤害 |
| 收益 / Income | 改动前后目标值的相对变化，不是装备单条属性的大小 |
| 魔灵潜质 / Trait | 4 个不重复的基础潜质及其等级；不是魔之楔槽位 |
| 和鸣增益 / resonanceGain | 满值 3、随队伍固定、非可培养项，与攻击加成同池加算；不是「溯源」 |
| 协战构筑关联 | 协战角色绑定的公开构筑 ID 与所选 A/B/C 配置 |
| 时间轴 / Timeline | 带轨道、时间与持续长度的技能/BUFF 事件，及可选生命比例曲线 |
| 快照 / Snapshot | 展开原始数据与运行参数后的可序列化数据，供 Worker 重建构筑 |

账号、资源、数据包安装与水合由外围模块负责。装配层查表构造等级化对象；计算内核只消费等级化对象。

## 实现决策

### 1. 模块边界

- 页面层承担路由、交互、浏览器存储、协战效果整理、分享、游戏导入与计算结果展示。
- 数据层提供配置结构、等级化对象、查表适配器、表达式与构筑计算。数据形状与纯规则以数据层定义为准，前端同名入口只是转引。
- 计算内核接收已构造的角色、武器、魔之楔、BUFF、怪物与时间轴，不自行访问 Pinia、localStorage、网络或前端基建。
- 查表适配器根据配置 ID 装配等级化对象；Worker 使用可序列化的原始数据快照重建对象，不静态导入主线程已水合的游戏表。
- 云端保存设置 JSON 与社区元信息；目标值按需调用共享内核计算，不由客户端上传数值作为权威结果。
- Agent 与代码沙箱是程序化调用边界，不替代配装规则，也不等同于公开构筑服务。

### 2. 配置结构与默认值

配置中不内嵌角色主键，调用方另外传入角色 ID；本地存储按该主键隔离。

| 字段组 | 字段与当前默认值 |
|---|---|
| 角色 | `charLevel=80`、`charSkillLevel=10`、`extraMastery=""` |
| 动作与目标 | `baseName=""`、`targetFunction=""`、`customVariables=[]` |
| 作战条件 | `hpPercent=1`、`resonanceGain=3`、`imbalance=false` |
| 敌人 | `enemyId=130`、`enemyLevel=80`、`enemyResistance=0`、`isRouge=false` |
| 武器 | 近战 ID 10206、远程 ID 20102；双方默认等级 80、精炼 5；首次创建可用角色专武替换对应槽 |
| A 配置 | `auraMod=31524`；`charMods/meleeMods/rangedMods` 各 8 空槽，`skillWeaponMods` 4 空槽 |
| 变体 | `modVariantIndex=0`、`modVariants=[]`，仅 A 初始存在 |
| BUFF | `buffs=[]`、`customBuff=[]` |
| 魔灵 | `petId=0`、`petLevel=3`、`petCoverage=1`、`petAutoCoverage=true`、`traits` 为 4 空槽 |
| 协战 | 两组角色、武器、构筑均以 `"-"` 表示未选；构筑变体均为 `"A"` |
| 特效 | `useGlobal=false`、`effectConfig={}` |
| DOT | 技能/近战/远程/同律频率均为 0，`forceOwnAdditionalDamage=false` |
| 时间轴 | `timelineDPS=false`；内联动作默认禁用，各动作、BUFF 组与 HP 列表为空 |

固定数据形状：

- 魔之楔槽为 `[modId, level]` 或 `null`；潜质槽为 `[基础潜质 id, level]` 或 `null`。
- 普通 BUFF 为 `[name, level, coverage?]`，覆盖率缺省表示 100%；自定义 BUFF 为 `[property, value]`。
- 自定义变量为 `[name, expression]`。变量定义与目标函数均保存表达式文本，而非函数对象。
- 每份额外变体包含 `角色/近战/远程/同律` 四组槽位与 `中枢` ID。
- `effectConfig` 使用 `m:<modId>` 与 `w:<weaponId>` 为键，不按显示名称合并不同品质装备。

### 3. 归一化、兼容与序列化

1. 外部设置在默认配置上补齐已知字段。未识别顶层字段、`undefined` 与不匹配的基础类型不写入；数组只检查是否数组，对象字段浅合并。
2. 这不是严格配置校验器：A 的历史 MOD 数组没有统一固定长度或逐槽合法性检查，普通 BUFF 条目也没有完整形状、等级或负覆盖率验证。不能声称任意 JSON 都能安全成为构筑。
3. 普通 BUFF 显式覆盖率小于 1 时保留第三项并舍入到 6 位小数；缺省或大于等于 1 时转为两项。此步骤不把负覆盖率钳制到 0。
4. 自定义 BUFF 数值舍入到 6 位小数，避免存档残留浮点尾差。
5. 协战角色名、武器名尽量转换为 ID；无法解析的历史字符串保留，以免直接丢失旧存档，但这不保证后续装配能成功。
6. 协战构筑 ID 只保留去掉首尾空白的有效字符串，其他值变为 `"-"`；协战变体仅接受不区分大小写的 A/B/C，其他值回退 A。
7. B/C 最多两份，各组槽位补到 8/8/8/4；槽位必须是含有限数值 ID 与等级的数组，数值四舍五入，不做装备存在性检查。非法变体条目补成空变体，保持字母下标稳定。
8. B/C 中枢接受有限正数 ID，否则存 0；读取 0 或无效中枢时沿用 A。激活索引四舍五入并钳制到已有变体范围。
9. 潜质去除非法档位与重复基础 ID，有效项压紧到前面并补足 4 槽。不存在的魔灵 ID 变为 0；突破等级取整数并钳制到 0–3，主动覆盖率钳制到 0–1。
10. 旧 BUFF 列表里可识别的魔灵主动、被动与潜质迁移到新字段并从列表移除；已有魔灵选择与潜质不被旧字段重复覆盖。未被归属解析器识别的名称不会被此迁移自动清理。
11. 配置本地自定义 BUFF 为空时，可读取旧全局 `customBuff` 存档；仅在迁移有效条目后删除旧键。
12. 序列化先归一化再生成 JSON；不追加独立 schema 版本，也不保存游戏数据对象或计算缓存。

### 4. A/B/C 魔之楔配置

- A 始终使用历史 `charMods/meleeMods/rangedMods/skillWeaponMods/auraMod` 字段；B/C 使用 `modVariants`，保障历史单配置存档继续可读。
- 变体只隔离四组 MOD 与中枢，角色等级、武器、BUFF、魔灵、敌人、表达式与协战等共享。
- 新增变体深拷贝当前激活变体的槽位与中枢，追加后立即激活；最多三份，达到上限返回失败值 `-1`。
- 只允许删除「当前激活且处于末尾」的 B/C；删除后激活前一份，A 不可删除。
- 请求不存在的槽位变体时读取 A；外部协战构筑缺少指定变体时实际展示 A。
- 装配、MOD 编辑与自动配装结果回写以当前激活变体为准，不覆盖其他变体。

### 5. 装备、特效、BUFF 与魔灵

- 角色槽限定按角色 ID、名称或元素匹配；武器槽限定按承载武器的类别或伤害类型匹配。武器槽没有有效承载对象时不可装备；未设置限定的装备视为通用。
- 武器 ID 0 构造零属性、无技能、无特效的空武器占位；其他不存在的武器 ID 抛错。不存在的角色或 MOD ID 在严格查表入口也抛错，而不是全部静默忽略。
- 普通武器等级限制为 1–80、精炼 0–5；带熔炉的武器固定为 0 级熔炼且使用独立潜能规则。潜能生效由角色原有或额外精通决定。
- MOD 最大等级按品质为金 10、紫/蓝 5、绿/白 3；属性按等级缩放，架势、条件条目及技能替换遵循数据定义的特殊规则，不能统一视为线性攻击加成。
- `useGlobal=false` 时使用本构筑特效配置，未设置的特效默认最大；`useGlobal=true` 时读取全局背包快照，缺失等级为 0。武器特效元素限定不匹配时为 0，不能被本地配置强行启用。
- MOD 自身词条与效果 BUFF 层分开汇总。特效中 `@` 前缀的属性进入 BUFF 层，不受该 MOD 所在武器槽的普通词条作用域限制。
- BUFF 等级按条目自身范围处理；覆盖率缩放数值加成，不是随机模拟 BUFF 的开关。动态属性表达式与动态代码遵循各自执行路径，不能承诺任意代码逻辑都自动按覆盖率缩放。
- 普通配置 BUFF 查表失败时设置适配器记录错误并跳过该 BUFF；角色、MOD 或武器严格查表失败仍可能终止构筑装配。
- 自定义 BUFF 在当前构筑内生成独立数据对象，不修改全局 BUFF 表；必须存在相应选中 BUFF 才按普通 BUFF 流程参与汇总。
- 魔灵突破等级为 0–3；技能有效值索引为突破加潜质加成并钳制到 0–4，显示技能等级为索引加 1。「老道」提升魔灵技能档位，不直接产生角色属性 BUFF。
- 潜质等级 1/2/3 对应稀有度 r3/r4/r5。只有关联了属性 BUFF 的潜质才通过普通 BUFF 汇总；其他潜质可仅展示说明或改变魔灵规则。
- 魔灵被动使用完整数值；主动按覆盖率缩放。没有登记 BUFF 的魔灵不凭说明文本自动产生属性。
- 自动覆盖率为「可解析效果持续时间 / 实际冷却」，实际冷却为原始冷却乘以 `1 - 潜质 CD 缩减`，结果限制在 0–1；无可解析持续时间或有效冷却时回退手动值。
- 自动覆盖率的 CD 缩减只从潜质读取，不把其他自定义来源一并纳入；构筑属性中的魔灵 CD 则按其属性汇总口径折算。
- 武器替换收益逐把替换对应槽并重算，用候选默认等级与精炼而非当前槽位等级；正确计入特效与精通。当前目标值为 0 时收益统一为 0，计算在克隆对象上执行。

### 6. 属性与伤害计算契约

#### 6.1 公开输入与输出

- `CharBuildOptions` 接收已构造的角色、近战、远程对象，必填 `hpPercent/resonanceGain/baseName`；可选四组 MOD、中枢、BUFF、敌人、目标表达式、自定义变量、时间轴、魔灵原始冷却与 DOT 参数。
- 引擎缺省技能等级 10、敌人等级 80、敌人 ID 130、目标函数「伤害」；HP 比例钳制到 0–1。这些是内核默认，不替代配置层及各调用方的默认值。
- `calculate()` 返回目标函数数值；`calculateAttributes()` 返回角色属性；`calculateWeaponAttributes()` 返回角色上下文及对应武器属性；`calculateByBasename()` 切换所选动作并返回属性与伤害结果。
- `calculateSkillDamage/calculateWeaponDamage` 的结果用于伤害乘区；字段表达式再结合基础值、防御与标签结算。不能把该方法返回的系数直接视为最终绝对伤害。
- 主动查表、错误降级、目标校验与求值是不同边界：内核无法补救任意外部装备 ID 与配置形状。

#### 6.2 面板与作用域

以 `r=resonanceGain`、百分比输入为小数：

| 项目 | 当前主要口径 |
|---|---|
| 角色攻击 | 基础攻击 × (1 + 攻击加成 + r) × (1 + 属性攻击) + 固定攻击，保留 2 位 |
| 角色生命 | 基础生命 × (1 + 生命加成 + r) + 固定生命，取整 |
| 角色防御、护盾 | 基础值 × (1 + 对应加成 + r)，取整 |
| 角色神智 | 不加入共鸣 `r`，按其自身加成口径 |
| 威力、耐久、效益、范围 | 基准 1；耐久上限 4、效益上限 1.75、范围上限 2.8 |
| 武器攻击 | 基础攻击 × (1 + 武器攻击加成) × 精通倍率 × (1 + 物理加成)，保留 2 位 |
| 普通武器精通 | 匹配为 1.2，不匹配为 1；原生同律为 1.4 |
| 暴击、暴伤、触发 | 各基础值 × (1 + 对应加成)，保留 2 位 |
| 武器攻速 | (射速或 1) × (1 + min(攻速加成, 2))，保留 2 位 |
| 多重 | 1 + 多重加成，保留 2 位；不会自动计入裸「伤害」 |
| 装填时间 | 基础装填 / (1 + 装填加成) |

- 属性按角色、近战、远程、同律作用域汇总。角色攻击加成不会直接进入武器攻击池，武器攻击与角色攻击仍可共同构成最终字段基础。
- 普通加成加算；独立乘法属性按 `各项(1+值)的乘积 - 1` 汇总；减伤按 `1 - 各项(1-值)的乘积` 汇总。
- 条件 MOD 与动态 BUFF 可依赖当前面板，汇总不是单次把所有数值机械相加；动态表达式非有限结果按 0，动态代码失败记录错误并按其上下文回退。
- 充盈威力包含角色直接加成及有效武器的 `max(0, 触发面板 - 1) × (1 + 对应充盈转化)`；继承型同律不重复计入。
- 召唤间隔为基础间隔除以 `1 + 召唤物攻速`，攻击次数由持续、延迟与间隔取整；相关面板按召唤规则处理，而不是普通武器一击。

#### 6.3 字段伤害与战斗条件

- 常规技能字段基础为「字段倍率 × 指定基础属性 + 平值」；通常基础为攻击，也可由数据指定为生命或防御。治疗字段不套普通伤害乘区。
- 昂扬乘区为 `1 + 昂扬 × clamp(hp, 0, 1)`；背水乘区为 `1 + 4 × 背水 × (1-h) × (1.5-h)`，其中 `h=clamp(hp, 0.25, 1)`，不是无限受益于更低血量。
- 200 级以下高级减伤系数为 1，200 级起为 `1 / (1 + (敌级 - 190) × 0.05)`。
- 护盾阶段只应用高级减伤；生命阶段防御系数为 `(1 - D / (300 + D - 10 × 等级差)) × 高级减伤`，限制在 0–1。等级差为 `clamp(min(80, 敌级) - 角色等级, 0, 20)`；`D` 为应用无视防御后的敌防御，技能另计技能无视防御。
- 技能通常为纯元素伤害；增伤池包含增伤、技能伤害及字段适用的召唤物伤害、元素或物理增伤，再计独立增伤、召唤独立、HP 乘区与属性穿透等。失衡开启时乘区为 `1.5 + 失衡易伤`；不是 `2.5 + 失衡易伤`。
- 普通技能不使用武器暴击与触发。普通武器字段通常用角色攻击与武器攻击构成基础，元素与物理成分分别结算；灾厄武器、继承型同律等有专门分支。
- 武器暴击率不在 100% 封顶，期望乘区为 `1 + 暴击率 × (暴击伤害 - 1)`，高低档由暴击率向上/向下取整决定；「未暴击」成员在溢出暴击情况下不保证真正没有暴击。
- 武器触发面板可大于 1，但直接触发结算钳制到 0–1；贯穿、切割、震荡分别按生命、护盾、战姿目标判定适用性，灾厄触发另依抗性条件处理。
- 伤害转换共享转换池，超过 100% 的有效转换按比例压缩；属性克制/逆克制根据当前抗性决定是否生效，零抗性不启用对应转换。技能转物理与武器转换路径不是同一公式。
- 「充盈」标签计 `1 + 充盈威力`，非充盈字段可按转充盈系数受益；二者互斥，转充盈不占普通转换池。
- 这些是稳定结算规则摘要，具体字段、异常与数据定义仍决定所用分支。不能从摘要推出所有技能都具有相同伤害结构。

### 7. 目标表达式、成员与 DOT

#### 7.1 表达式语法

- 支持数字、中文或字母标识符、下划线、间隔点、方括号技能标签、括号、一元正负，以及 `+ - * / % //`；`//` 为向下取整除法，不是注释，除零或模零返回 0。
- 支持 `命名空间::字段`、字段成员与临时属性后缀，例如 `Q::伤害`、`伤害.N`、`伤害{增伤:0.2}`。单冒号、尾随非法 token、空临时属性、重复后缀属性会报错；二元运算符后直接负号如 `10+-20` 不被接受。
- 命名空间可指定角色、近战、远程、同律，接受对应英文别名；技能可按映射名称或 E/Q/P 引用。名称与游戏数据绑定，字段名存在首个模糊包含匹配，不保证所有名称唯一。
- 无命名空间的解析优先级是函数参数、自定义变量、技能字段、角色属性、武器属性；`!` 可强制属性查询，避免与字段冲突。
- 临时属性只作用该字段；普通角色临时加成常作用最终面板，武器加成通常乘基础值，固定攻击/生命加平值，不能将所有临时属性解释为 MOD 百分比。
- 内置函数有 `min/max/floor/ceil/or/log/power/hp`。`or` 取首个非零值，但参数全部求值，不是短路条件语句；`hp(x)` 返回对应 HP 下的昂扬与背水乘区。
- 自定义变量保存名称与表达式；名称形如 `fn(x,y)` 时声明自定义函数，检查参数与实参数量。递归或循环在重入处返回 0，不保证整条外围表达式归零。
- 宏以文本展开，不自动加括号。未知属性求值为 0，未知函数可能抛错；`validateAST()` 返回错误信息或无错误，不等于目标函数数值。
- 目标包装器捕获求值错误并返回 0；语法解析失败还会将目标改为「伤害」。`0` 本身无法区分合法零输出与错误降级，需结合校验与日志判断。

#### 7.2 常用目标与成员

| 表达式 | 当前含义 |
|---|---|
| `伤害` | 当前字段的期望值，不自动乘多重或换弹周期 |
| `DPH` | `or(多重,1) * 伤害` |
| `DPS` | `or(攻速,1+技能速度) * or(多重,1) * 伤害`，不计换弹 |
| `伤害.N` | 去掉昂扬、背水后的该字段伤害，仍保留防御等其他乘区 |
| `Q::伤害` | 映射到 Q 的技能字段伤害 |
| `DOT伤害` | 显式加入 DOT 计算结果，裸伤害不自动附加它 |

目标函数可用于显示、比较、收益与自动配装，不能统一标为「伤害」或「每秒伤害」，尤其是用户自定义加权目标。

#### 7.3 DOT

- 技能、近战、远程、同律各保存每秒造成伤害次数，默认 0；0 表示该来源不参与。DOT 是频率估算，不是逐次随机模拟。
- 正触发率的最大可用命中频率为 `1 / (0.4 × 触发率)`；自身元素的多个来源共享最高来源上限，并按技能、近战、远程、同律顺序分配。
- 当前 DOT 求和以 `(角色攻击 + 来源武器攻击) × 0.2 × 6 × 4 × (1 + 充盈威力) × (1 + 增伤) × 昂扬 × 背水 × 抗性/穿透加权频率` 为核心。
- DOT 不使用普通伤害的防御、暴击、独立增伤与失衡乘区；追加伤害自身元素选择还受 `forceOwnAdditionalDamage` 控制，不能把武器伤害系数完整套到 DOT 上。

### 8. 内联动作与时间轴输入

- 原始时间轴包含名称、轨道名、事件列表与可选 HP 曲线。事件保存轨道索引、名称/表达式、起点秒数、时长秒数及可选源索引；轨道是组织展示的结构，不是独立攻击乘区。
- 内联顺序动作字段为表达式 `s`、时长/延迟 `d`、可选次数 `t` 与 BUFF 组索引 `b`；次数默认 1。所有顺序动作按 `d × t` 推动总时长，每次事件放在当前起点，再将时间推进 `d`。
- 指定有效 BUFF 组时，组内 `[BUFF 名称, 等级]` 转成与该动作起点、时长相同的 BUFF 事件。每条原始顺序动作获得各自的技能轨道与 BUFF 轨道。
- 背景动作字段为表达式 `s`、间隔 `i`、可选次数 `t`、每轮延迟 `d` 与 BUFF 组索引 `b`。当前转换只消费表达式、间隔、次数与延迟，不使用背景动作的 BUFF 组字段。
- 背景动作从 0 开始，每轮先加延迟，再按间隔生成至多 `t` 个事件，循环填满顺序动作总时长；背景事件的时长等于间隔。最后一个事件可以延伸超过顺序总时长，转换器不裁切它的时长。
- 只有背景动作、没有顺序总时长时，不生成背景事件。当前转换器不替调用方强制校验所有参数；时间推进必须为正，零间隔且零延迟等组合不能保证循环结束，非法表达式也需要另行校验。
- 内联 HP 曲线直接进入时间轴，不由转换器自动排序、去重或计算。
- 本地独立时间轴按角色名保存；内联 `actions` 随构筑配置保存。两者不是同一份存档，共享适配器只使用调用方显式传入的时间轴，不自动从 `actions` 转换。

#### 8.1 时间轴执行

- 时间轴总时长为最大事件结束时间。`calculate()` 开始时重置敌人 HP；按事件原数组顺序处理技能，并非自动按起点排序。
- 等级 `lv` 为真值的事件识别为 BUFF，必须已携带等级化 BUFF 实例；`lv=0` 被当作技能。应先由适配器进行时间轴 BUFF 水合。
- 技能开始时采样适用 BUFF，区间包含起点与终点；BUFF 轨道从当前技能轨道开始，到下一技能轨道之前。轨道键当前用默认排序，不是严格数字排序。
- HP 曲线在技能开始时线性插值，超出首尾则使用首尾值；没有逐帧在持续期间更新 HP 或 BUFF。调用方应提供按时间组织的有效 HP 数据。
- 每个技能事件先单独求值，再按事件类型乘算次数，最后累加进总值：召唤动作按 `floor((min(召唤持续, 事件持续) - 延迟) / 间隔)` 求次数；连续武器按持续、弹匣、装填与攻速折算次数。两处次数只作用于该事件自身的伤害。
- 时间轴 BUFF 按事件生效区间附加到该事件的构筑副本上（`applyBuffs`）：与原有 BUFF 同名的叠加等级、不重复入列，新 BUFF 按生效槽位入列（复合 BUFF 同时进普通槽位与 code 槽位）。
- `timelineDPS=true` 时将累计值除以时间轴总时长；总时长为 0 时返回 0，不产生 `Infinity`/`NaN`。
- 召唤物事件的可用时长被 `min(召唤持续, 事件持续)` 截断，短于召唤攻击延迟的事件会得到非正的攻击次数，进而产出负值或 0 伤害；这是当前取整口径的直接结果，未做下限保护。

### 9. 收益、耐受、极化与配装码

- 增加收益为「增加后目标 / 当前目标 - 1」；移除收益为「当前目标 / 移除后目标 - 1」。不同入口对零值及非有限值的保护不统一，不能约定所有收益都有限。
- 普通候选 MOD 使用临时槽追加评估，不等于在指定实际槽位替换。已装备项的精确收益在克隆构筑中实际移除对应槽位或同名 BUFF 后重新计算。
- 武器列表使用前述整槽替换收益，不能与任意 `calcIncome()` 调用混为同一口径；潜质可能通过改变魔灵技能档位或主动覆盖率计算收益。
- 基础容量为 `20 + 角色或武器等级`；角色另计中枢最大耐受，原生同律使用角色等级。
- 单套极化计算按高耐受优先处理，匹配极性后的消耗为 `ceil(耐受/2)`。多套共享极性时，同极性半价，异极性消耗为 `ceil(耐受×1.5)`。
- 共享方案按第一套优先的贪心规则返回极性数量、中枢、成本、槽位及 `ok/reason`，不保证全局最少成本；容量不足的结果与目标伤害值是两个不同维度。
- 配装码按游戏展示槽序 `[1,3,4,2,5,7,8,6]` 编排，ID 为大写四位 base36，空槽记 0；角色头为 `C+角色ID` 并附中枢，武器头为 `W+武器ID`。
- 当前原生同律配装码头取远程武器 ID。解析跳过前五字符，不校验头部归属，只返回 ID 列表，不直接应用到构筑；不能把它描述为含等级、特效与全配置的 JSON 分享格式。

### 10. 自动配装与 Worker

- `autoBuild()` 在克隆构筑上搜索并返回 `newBuild/log/iter`，不直接写页面或当前设置。只处理包含的类型，其他类型与中枢保持不变。
- 保留类型中已装备的非空 MOD 被压紧为不可替换前缀；搜索只能替换本次生成的槽位。候选依据类型、极性、元素、限定、名称/系列互斥与契约者数量等规则筛选。
- 候选 count 为 0 当前通过 `count || Infinity` 当作不限数量，不能将 0 解释为禁用候选。
- 搜索先用追加收益评分，处理需要组合生效的条件 MOD，再填正收益槽；同分比较词条数后可能随机选择。替换生成部分的低收益项时，只有真实总目标值提高才接受。
- 最多 20 轮，状态无变化或重复时结束。是有界启发式搜索，不是穷举或全局最优证明；不检查耐受/极化容量，优化后的方案仍需单独检查是否能装备。
- UI 自动配装默认使用库存，不默认搜索替换近战或远程武器；计算受面板打开、更新开关与依赖变化控制。武器是否搜索、包含与保留类型属于独立持久化选项。
- 收益 Worker 接收构筑与候选快照，返回收益或错误；自动配装 Worker 返回日志、优化后快照及逐槽收益，均不访问页面状态或回写设置。
- Worker 快照包含原始角色/武器/MOD/BUFF/怪物数据、等级、特效、覆盖率等；使用 structured clone 可传形状重建计算对象，不传类方法，也不静态导入主线程游戏表。
- 页面审阅结果后应用：写两把武器的 ID、等级、精炼，并替换当前激活变体的四类 MOD，随后更新显示。不替换其他变体、中枢、BUFF 或整个设置，不自动保存为命名方案。
- Worker 错误当前主要写 console，不能承诺存在明确用户可见失败状态。

### 11. 公开构筑 GraphQL 契约

业务入口为 `/graphql`，身份从请求头 `token` 的 JWT 解析，无效 token 作为匿名请求。读取可以匿名，写入按下表鉴权。

| 操作 | 输入 / 默认值 | 可观察结果与权限 |
|---|---|---|
| `builds` | 可选 `search/charId/userId/sortBy`；`limit=20`、`offset=0` | 返回构筑数组；匿名可读 |
| `buildsCount` | 可选 `search/charId`，不接受 `userId` | 返回匹配数量，不能直接作为作者筛选列表的总数 |
| `recommendedBuilds` | `limit=10` | 仅推荐项，按创建时间降序 |
| `trendingBuilds` | `limit=10` | 按浏览量、点赞数依次降序，无时间窗口 |
| `build` | 必填字符串 `id` | 查询详情并增加一次浏览；不存在时报错 |
| `createBuild` | `input` 包含必填 `title/charId/charSettings` 与可选 `desc` | 须登录，作者固定为当前用户 |
| `updateBuild` | 必填 `id` 与完整 `input` | 须为作者或管理员；替换输入字段，不是局部 patch |
| `deleteBuild` | 必填 `id` | 作者或管理员可删，成功返回 true |
| `likeBuild / unlikeBuild` | 必填 `id` | 须登录；点赞状态按当前用户记录 |
| `recommendBuild / pinBuild` | 必填 `id` 与对应布尔标记 | 仅管理员；设置推荐/置顶，不更新时间 |
| `clearBuildTargetValueCache` | 无参数 | 仅管理员；返回清除缓存条目数 |

- 构筑包含非空 `id/title/charSettings/userId` 字符串、整数 `charId/views/likes`、毫秒时间戳 `createdAt/updateAt`；可空字段为 `desc/isRecommended/isPinned/isLiked/user/targetValue`。
- GraphQL 响应只包含 selection 选择的字段。选 `user` 才加载用户关系，选 `targetValue` 才计算；生成客户端包装常常只返回部分字段，不能把完整类型声明当成实际响应。现有列表与详情包装未选 `targetValue`。
- 列表筛选为 AND：标题 SQL LIKE `%search%`、角色 ID 与作者 ID 精确匹配；空 search/userId 与角色 ID 0 不形成条件。
- `sortBy="likes"` 按点赞降序，`"views"` 按浏览降序，其他值按更新时间降序。置顶不参与列表排序；分页参数直接交给数据库，没有业务上限、非负验证或稳定次级排序。
- 详情每次实际执行增加浏览量，不排除匿名、作者或重复访问。列表查询不增加浏览，客户端缓存命中不触发服务端执行。
- 创建与更新仅额外检查 `charSettings` 字符串长度不得超过 20,000，等于上限允许，长度按 JavaScript UTF-16 单元计；不验证它是合法 JSON、角色存在或配装有效。
- 重复点赞报错；取消点赞没有先检查现有点赞记录，重复取消可能使数据库计数为负。当前取消响应把显示值钳到 0，不能将该接口描述为幂等。
- `targetValue` 不落库。服务端解析配置后调用共享计算适配器，失败或非有限值返回 null；计算采用进程内按构筑 ID 缓存，并将并发同 ID 请求合并为一次计算，失败不缓存。
- 更新角色 ID 或配置原文、删除构筑时单条缓存失效；仅改标题或描述不会失效。游戏数据更新不能靠缓存键自动识别，需显式清缓存；不同进程不共享缓存。

### 12. 程序化 BuildApi 与 Agent

脚本使用 `build` 对象，全部方法为异步接口，必须等待其结果；公开操作按领域命名，而非通用 `get/set/calculate/autoBuild`。

| 分组 | 方法与语义 |
|---|---|
| 当前读取 | `state()` 读取语义状态与伤害；`damage()` 读取目标值，异常或非有限值回退 0；`attributes()` 读取属性；`raw()` 返回完整设置副本 |
| 角色与装备 | `char/level/settings/weapon/mod/mods/aura`；单槽与整类 MOD 替换、角色与武器设置；整类替换未给的位置清空 |
| 变体 | `variant/addVariant/removeVariant`；遵循 A/B/C 的新增、切换与末尾删除规则 |
| 加成与环境 | `pet/trait/traits/buff/removeBuff/buffs/customBuff/team/enemy/base/target/variable/dot` |
| 配置交换 | `export()` 输出设置 JSON；`import(string或partial)` 归一化后覆盖；`patch(partial)` 浅写已有键；`reset()` 恢复默认但保留两把武器 ID |
| 独立试算 | `simulate(json, charName?)`、`compute.build(idOrName, partial)` 创建独立构筑视图；`current()` 创建当前构筑视图 |
| 求解 | `autoSolve` 支持背包、包含类型、保留类型、近战/远程搜索与是否应用；缺省读取持久自动配装选项，`apply` 默认不应用 |
| 数据与工具 | `compute.char/mod/weapon/buff/pet/monster` 返回等级化数据；`data.mods/weapons/chars/buffs/pets/traits` 查询本地数据；`util.normalize/serialize/defaults/clone` 处理配置 |
| 页面兜底 | `ui.readPage/click/type/select/press`，限配装页上下文 |
| 日志 | `log()` 返回 API 实例累计日志，最多 200 条，不因每段脚本开始而清空 |

- 写入一般返回含 `ok/message`、可选 `error/damage` 的结果，并直接生效；不是事务，不自动回滚。
- `buff()` 当前也是全量替换 BUFF 列表，不是单条追加；`effect()` 修改全局背包特效等级，不写本构筑 `effectConfig`。配置写入并不替调用方强制所有 UI 配装约束，协战构筑 ID 也不自动去云端验证。
- `export/import` 不包含作者、点赞、浏览或服务器构筑 ID，也不自动切换角色；`patch()` 不经过完整归一化。
- 独立构筑视图支持 `damage/attributes/bonus/fullness/cost/mods/weapons/skills/variable/eval/raw`；独立试算不修改当前设置。其缓存最多 64 条，按角色 ID 与配置 JSON 区分，不包含库存版本，故不是自动随背包更新的权威快照。
- `autoSolve` 返回是否应用、目标值、武器、MOD 文本与迭代数；应用时写当前变体 MOD 与武器，不发布云端构筑。
- Agent 的 `run_code` 代码最长 8,000 字符，默认超时 8 秒；结果包含 `ok/value/logs/error/ms`，`value` 是序列化文本。页面读写与程序接口自动求解实际由主线程执行，快照进入 Worker 后再提供局部查询。
- 超时可终止执行 Worker，但不撤销已完成的页面或库存写入，也不能承诺同步主线程求解立即停止。
- 配装聊天按角色名保存在本地 IndexedDB，与公开构筑服务分离；BuildApi 没有发布构筑或云端保存聊天的方法。
- 独立试算与 Worker 快照有装配差异，见「调用入口差异」，不得推定 Agent 试算与页面输出逐项等价。

### 13. 页面工作流、持久化与比较

#### 13.1 路由和初始化

- `/char` 为角色列表；`/char/:charId` 为本地构筑；`/char/:charId/:buildId` 为分享入口；`/char-build-compare` 为多配置比较。
- 角色 ID 来自路由。主页面等待数据包就绪及角色可用，未准备好时返回空构筑占位，不将空数据当成实际角色计算。
- 默认 `simple` 简洁模式，展示装配总览；`pro` 专业模式使用编辑器。模式在 `char-build-view-mode` 持久化；简洁子组件不直接编辑配置，可发出切换模式与使用分享构筑事件。
- 页面更新时将不存在的敌人 ID 回退到 130，空基础动作可设为角色首个技能；补齐/裁剪 A/B/C 的固定槽位与潜质槽，过滤形状不合法的自定义变量。这些是主页面更新行为，不属于全局归一化保证。
- 主页面装配异常会记录错误、删除该角色的当前 `build.<charId>` 存储键并退回空构筑。不能将所有坏存档描述为无损恢复。

#### 13.2 当前配置、命名方案与交换

| 保存对象 | 存储位置 / 口径 |
|---|---|
| 当前配置 | localStorage `build.<charId>`，按角色 ID 隔离 |
| 命名方案 | localStorage `project.<charId>`，保存方案名、当前选中名与完整设置快照 |
| 分享来源 | localStorage `buildRemote`，角色 ID 到远端构筑 ID 的映射 |
| 独立时间轴 | localStorage `timeline.<角色名>`，保存该角色时间轴列表 |
| 展示偏好 | `char-build-view-mode`、`build-collapsed-sections` |
| 自动配装设置 | `autobuild.setting`，不是当前构筑设置的一部分 |
| 配装对话 | IndexedDB，按角色名归属，不上传公开构筑表 |

- 加载命名方案深拷贝并归一化后替换当前设置，记录选择、清空分享来源、同步目标函数并更新页面。
- 保存方案用当前完整设置深拷贝覆盖快照。新建名称为空则取消；同名新建直接覆盖已有方案，不额外创建第二份同名记录。
- 重命名必须非空且不与其他方案重名，当前选中名随之更新。删除需要确认；删掉当前选中方案后清空选择，当前编辑配置不会因此自动重置。
- 剪贴板导出为归一化 JSON。导入先去空白，空内容、解析失败或非对象顶层提示错误；对象判定没有排除数组，亦不是完整 schema 校验。成功后替换当前设置并同步目标函数，不携带角色主键或服务器元数据。
- 页面重置恢复该角色默认设置，可自动装备专武，并清空分享来源；与程序接口仅保留现有武器 ID 的 `reset()` 口径不同。

#### 13.3 分享和游戏装备导入

- 共享路由挂载后按 `buildId` 请求详情，解析设置 JSON、归一化、替换当前配置并记录来源 ID；失败显示错误。加载操作不自动新增命名方案，不自动切换到返回构筑的角色，也没有将角色 ID 与链接角色逐项验证的独立流程。
- 发布序列化当前配置，提交标题、描述与路由角色 ID；成功复制 `/char/<charId>/<buildId>` 链接，失败显示错误。若分享列表处于懒渲染折叠态，不强行调用未挂载实例，展开后再拉取。
- 分享组件负责搜索、排序、分页、点赞、编辑、推荐、删除与「使用」；使用事件把设置与远端 ID 交父页面，父页面执行替换。
- 游戏导入依赖已登录 DNA API；缺少账号、没有对应角色/武器或详情获取失败时显示错误并不应用结果。角色装备从角色详情读取，含独立中枢；武器详情按其对应类型读取。
- 游戏 MOD 按展示顺序重排，无法解析的条目转空槽；角色 MOD 等级用远端条目等级，武器 MOD 等级用本地背包等级。不能声称两条路径均完全还原游戏装备的远端等级。
- 导入结果写当前激活变体，不覆盖其他 A/B/C；角色和武器装备导入不是全量账号、角色配置或云端方案同步。

#### 13.4 比较页

- 初始一份「配置 1」，每份可独立选角色与项目，项目第一项为当前配置，其余来自该角色本地方案。新增复制最后一份后改名，至少保留一份。
- 所选设置先构造基础构筑，再创建最终比较构筑，追加本页的 MOD 与 BUFF；追加 MOD 上限为角色/近战/远程各 8、同律 4。
- 追加 BUFF 合并到已有列表末尾，不全量替换项目 BUFF；追加配置仅用于比较，不回写本地命名方案。
- 比较属性、武器属性与计算目标值；独立挑选的时间轴与主页面内联动作并不等价，各装配入口保留差异如下。

### 14. 调用入口差异

下表描述当前真实参数传递，不是待实现设计。空白/缺失能力不应由调用者猜测补齐。

| 参数 / 能力 | 主构筑页面 | 比较页最终构筑 | 设置适配器 / 独立试算 | Worker 快照往返 |
|---|---|---|---|---|
| 当前 A/B/C 和中枢 | 使用 | 使用 | 使用 | 已激活后的具体装备，不携带全部变体 |
| 自定义变量 | 传入 | 基础与最终构造未传入 | 传入 | 传入 |
| 额外精通 | 先按角色允许列表筛选再传入 | 未传入 | 原值传入 | 传入 |
| DOT 配置 | 传入 | 基础传入、最终遗漏 | 传入 | 传入 |
| 魔灵原始 CD | 传入 | 基础传入、最终遗漏 | 传入 | 类型和恢复器支持，生产快照遗漏 |
| 内联动作 | enable 时转时间轴 | 不转换，仅找命名轴 | 不自动转换 | 不携带 |
| 独立时间轴 | 从本地按名称查找 | 从本地按名称查找 | 仅显式第四参数 | 不携带 |
| `timelineDPS` | 有设置控件，构造未传 | 未传 | 传入 | 标志传入，但时间轴本身缺失 |
| 肉鸽 `isRouge` | 配置存在，未构造对应怪物模式 | 未构造对应怪物模式 | 配置值未消费 | 实例怪物已带模式时可携带 |
| 协战武器类别 | 传 `teamWeapons`，构造器未消费 | 基础传 `teamWeapons`，最终复制类别数组 | 将数值 ID 解析为 `teamWeaponCategories` | 传类别数组 |
| 自定义 BUFF | 经选中 BUFF 实例注入 | 经 BUFF 实例注入 | 传独立 customBuff 与选中 BUFF | 已选中的原始 BUFF 可携带；独立 customBuff 列表遗漏 |

- `teamWeapons` 虽在公开选项中声明，当前构造器实际只读取 `teamWeaponCategories`，页面传入武器列表不自动变成类别；不能仅凭调用处有该字段便认定生效。
- 服务端目标计算、程序接口独立试算及其自动求解不额外提供设置适配器的时间轴参数，因此配置中的 `actions` 不自动形成服务端或独立输出时间轴。
- 共享同一内核仅保证实现来源相同，不保证装配输入一致。主页面、比较、Worker、服务端与 Agent 的数值不能直接互为精确回归预期，需先比较上述参数。

### 15. 已知限制

以下为当前实现的确定缺口，不是本文承诺修复的功能。

- 配置不是完整校验器：非法 JSON 形状、越界等级与负覆盖率不保证被拒绝。
- 主页面装配异常会删除该角色当前配置键，属有损恢复。
- 召唤物事件时长被 `min(召唤持续, 事件持续)` 截断，短于攻击延迟的事件产出非正次数与负值伤害，未做下限保护。
- Worker 快照不完整（见调用入口差异表），自动配装不检查耐受/极化容量。
- 部分接口非幂等（取消点赞），部分写操作是全局写入（`effect()`）。

## 测试决策

### 原则与边界

- 回归主要使用「设置装配为构筑，再读取属性、伤害、目标值或优化结果」这一现有公开边界；表达式、容量与序列化只在有独立契约时单独验证，不检查内部缓存布局或遍历顺序。
- 交互流程用真实页面入口验证；云端权限与查询行为用 GraphQL 业务入口验证。Worker 与服务端属于部署边界，不能仅凭内核单测通过便认定跨端一致。
- 对计算值使用有明确战斗条件的固定样例与浮点容差；比较或搜索测试断言可观察结果、约束满足与原始构筑未被污染，不依赖随机搜索恰好选中某一组合。
- 时间轴相关行为以真实技能数据驱动（召唤物事件使用召唤持续时间、攻击延迟、攻击间隔三个字段），避免用空字段构造恰好不触发分支的样本。
- 装配函数是 UI、Worker 与 Agent 三条真实入场路径的公共入口，应作为回归主缝。现有内核测试多数直接构造计算实例，未覆盖该映射。
- UI E2E 应遵循项目的 Bun.WebView 约定，不使用 Playwright。

## 补充说明

### 使用规格的限制

- 本文是当前实现的逆向快照，不是未来版本的承诺。新增功能应另写变更规格，避免把待实现条目混入现状。
- 领域词汇优先使用「魔之楔 / 中枢 / 同律 / 协战 / 魔灵潜质 / 和鸣增益」；接口字段保留源代码原名，避免译名掩盖序列化契约。
- 游戏数据更新会改变具体数值、技能名与候选集合；稳定契约是配置形状、作用域、默认策略与错误处理，不是某套配装长期排名第一。

### 关键不变量

实现改动时必须遵守的硬约束：

1. 新增任何「改属性」入口必须同时递增对应属性版本号，否则静默返回旧缓存表。
2. 乘法加成不能从加和表导出（`Π(1+v) ≠ Σv`），须走独立乘算查询路径。
3. MOD 同系列只能带一件（基础互斥系列外另有特殊系列）；契约者不受限。
4. 触发率允许溢出 100%，加成池不含武器自身加成；充盈威力按溢出部分乘转化率累加。
5. 武器切换后需移除不兼容魔之楔。
6. 新增配置字段必须同时改默认值、归一化与序列化三处。
7. 变体槽位读取必须走取槽函数，不得直接访问主字段。
8. 计算层不得 import 前端模块，需要外部能力时注入并提供默认值。
9. 同名形状只保留一份，前端侧转引。
10. 时间轴每事件的次数必须只作用于该事件自身伤害，不能乘在累计总值上。

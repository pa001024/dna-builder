# packs/dna — Duet Night Abyss 规则包

按 `specs/buildhub-core.md` 实现。数据**直接读上游 datapack**（`datapack/modules.json`，
与 `crates/dob-calc-core/tests/fixtures/modules.json` 同源），没有独立的导出器或中间格式。

## 数据来源

`pack.toml` 用 `dataset = "<文件>#<模块键>"` 选择 datapack 里的模块：

```toml
[[data]]
name    = "mods"
dataset = "datapack/modules.json#mod.data"
schema  = "Mod"
key     = "id"
```

schema 的字段名与上游 `*.data` **逐字一致**（`名称` / `类型` / `属性` / `加成` / `生效`），
不做重命名、不裁剪、不展开。

## 解析层：上游给的是分量键

上游已经把自然语言描述解析成**分量**，pack 不再自己拆：

| 数据里的键 | 不是 |
|---|---|
| `雷属性攻击: 0.18` | `属性攻击: {雷: 0.18}` |
| `切割攻击: 0.2` | `物理: 0.2` + `限定: 切割` |
| `秽兽增伤: 0.07` | `歧视: 0.07` + 目标类型 |

因此 `panel` 是**扁平分量**的汇总，没有任何按元素嵌套的表。引擎没有字符串拼接，
所以「元素 → 分量键」的词表写在 pack 里（`attack_key` / `element_bonus_key`）——
游戏有哪几个元素、每个元素的分量键叫什么，本来就是 pack 的职责。

同一个键的取值形状有两种，必须分开：

| 位置 | 形状 | 语义 |
|---|---|---|
| `加成` | `Num` | 直接相加 |
| `加成` | `[v1, v2, …]` | **按 MOD 等级取值**（`at_level`，超出末尾取最后一档） |
| `生效` | `Num` | 条件成立时相加 |
| `生效` | `[斜率, 上限]` | `min(条件值 × 斜率, 上限)` |

`生效.条件` 是全称合取，第三项可缺省（`["单手剑","*"]`）。条件键取值优先级：
`*id` → 重复次数；极性键（`D趋向` 等）→ 极性计数，为 0 时回退显式值；其余 → 显式值。

## 乘区（对齐 `dob-calc-core/src/damage.rs`）

```
攻击 = round2(基础攻击 × 等级倍率) × (1 + 攻击 + 共鸣) × (1 + 属性攻击 + 该元素攻击)
伤害 = 攻击 × 倍率
     × (1 + 增伤 + 技能伤害/武器伤害 + 元素/物理增伤)   ← 同池加算
     × (1 + 追加伤害)                                  ← 独立乘区
     × 暴击
     × 独立增伤
     × [(1 - 抗性) × (1 + 属性穿透)]                    ← 穿透与抗性同乘区
     × 血量（昂扬/背水）
     × 防御
```

`属性穿透` **不是**独立乘区：它与抗性在同一个乘区里相乘，下限 0。
DoT 不吃暴击、不吃防御（`damage-mechanics.ts`「DOT 伤害」）。

属性汇总口径（已实现）：

- `加成` 数组按 **0 基等级索引**取绝对值；标量按 `值/(满级+1)×(等级+1)` 缩放；
  `神智回复` / `最大耐受` 向上取整；架势 MOD 与「换生灵/海妖」减伤取满级。
- `生效` 的 `[斜率, 上限]` 是 `min(条件值 × 斜率, 上限)`；条件键取值按
  `*id → 重复次数`、极性 → 极性计数、其余 → 显式值。
- 武器 `加成` 按 `(精炼+5)/5` 缩放；带 `熔炉` 的武器不缩放、精炼固定 5。
- 武器特效（`effect.data`）按 `(精炼+5)/10` 缩放，`限定` 非空时只对同元素生效。
- BUFF 按等级缩放：标量 `(值/a)×(1+(等级−lx)/b)`，数组按等级索引；潜质与魔灵按名称挂 BUFF。
- `<元素>MOD属性` 对元素系列 MOD（狮鹫/百首/契约者/换生灵）的词条加权。
- 角色作用域只汇总角色槽 MOD；武器作用域由 `weapon_panel` 计算（基础值 × 作用域词条）。

## 表达式语言

`Config.target_function` 是一段文本，由 pack 自己词法分析 + 递归下降求值：

- 数字、`+ - * / %`、一元负号、括号
- `min/max/floor/ceil/abs/or`
- 标识符与 `[标识符]` → 属性；`命名空间::名字` → 作用域（角色 / melee / 近战 / ranged / 远程）
- 自定义变量（`Config.custom_variables`，可递归，带环检测）

引擎原语新增 `is_num` / `is_list` / `str_len` / `str_at` / `str_slice` / `str_eq`
（文本索引与形状判别都是语言级能力，不含游戏概念）。

  - `buff_table_of`：同理把 BUFF 池按键归并成表（等级链每 BUFF 只解析一次）。
  - `mods_of_kind`：用引擎的 `dedup_by` 取代「每个槽位 `find` 整表」的 O(n²) 去重。

  **否决的尝试**：把四类 MOD 桶放进 `CondCtx` 下发（T 能降到 61ms），但 B 路径
  退化 +15%（最优路径变慢），已整体回退；`R::CallStatic` 接 memo 也更慢 +17%。

  关键口径（均由引擎插桩实测确定）：
  - 武器池的增伤池含**武器面板增伤**（`melee::增伤 0.6`；角色面板为 0）。
  - 武器触发率要并入**武器特效层的 `触发`**（`10299` 特效的 `1`），
    远程还并入角色槽穿透池 —— 实测 `近战 0.9`、`远程 1.46`、`充盈转化 1 / 3`。
  - `充盈威力 = 角色 MOD 0.48 + Σ max(0, 触发率-1) × 充盈转化 = 1.38`。
  - `角色::[攻击]` 是引擎特殊标识符：`攻击 × 防御 × 抗性 × 增伤池 × 血量 × 穿透`。
  - 表达式后缀 `{转属X:比例}` 会按转换池重分配伤害分量（`skip_suffix` 实现）：
    抗性 < 0 时只有 `转属逆` 生效（`(1-0.5)/(1-抗性)`），`转属克` 被忽略；
    `转震荡` 等物理键为 `物理池/(抗性因子 × 元素池)`。
    实测 `转属克 1.0`、`转属逆 0.1`、`转震荡 0.17119`，三项与引擎逐位一致。
  - 字段伤害的结合顺序须与引擎 `damage.rs` 一致：
    `base = lv × (威力 × (攻击 × 继承))`，`expected = (base × 增伤) × (暴击 × common_more)`，
    `common_more = 血量 × (独立 × 追伤 × 召唤物独立 × 失衡 × 穿透)`。
    逐步相乘会差 1-2 ULP（此前 `[皇帝]伤害`、`[战车]伤害` 因此差 1 ULP，已修正）。
  - 数字字面量按整数累积后一次除法（`3.167` 曾因逐位加 `0.1` 得 `3.1670000000000003`）。

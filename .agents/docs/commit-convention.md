# 提交规范

本仓库历史提交以中文为主，标题格式为 `<type>(<scope>): <摘要>`。本文约定标题、正文、拆分粒度与提交前自检。

## 标题

```text
<type>(<scope>): <中文摘要>
```

- **type**：必填，见下表。
- **scope**：可选，写改动所属的模块 / 功能，使用仓库中的模块名、路由名或功能名（如 `node-editor`、`afk`、`server/rag`）；跨模块或无法归类时省略，不要臆造。优先使用小写 kebab-case；历史遗留的组件名（`RankingManagement`）或中文功能名（`密函`）不强制回改。
- **摘要**：一句话说清“做了什么”，建议不超过 50 字，不以句号结尾。避免 `update`、`fix bug`、`修改代码` 这类空泛描述，也不要在标题里罗列文件名。

| type | 用途 |
|---|---|
| `feat` | 新功能 / 新能力 |
| `fix` | 修复缺陷 |
| `refactor` | 重构（对外行为不变） |
| `perf` | 性能优化 |
| `docs` | 文档（含 `AGENTS.md`、`specs/`、`.agents/docs/`） |
| `test` | 测试用例调整 |
| `build` | 构建脚本、依赖、子模块、版本号 |
| `ci` | CI 配置 |
| `chore` | 其他杂项（格式化、工具脚本等） |

历史提交里出现过 `doc:`，统一写作 `docs:`。

## 正文

标题与正文之间空一行。单一变更可以省略正文；涉及原因、口径或影响面时写一段说明。

**多个变更项一律写成 `-` 列表**，每行一项，动词开头：

- 新增 …
- 修复 …
- 重构 …
- 调整 …
- 移除 …
- 优化 …
- 更新 …

正文描述行为与影响，不要写文件清单（避免“修改 xxx.vue / yyy.ts”）。同一改动涉及的测试、i18n 与必要文档放在同一个提交里，除非它们本身是独立改动。

破坏性变更在 type 后加 `!`（如 `feat!:`、`refactor!:`），并在正文首行写明迁移方式。

## 拆分粒度

- 一个提交只做一件事：功能、修复、重构、构建 / 版本、文档分开。
- 重构与行为变更分开提交，便于 review 与回滚。
- 按依赖方向排序：底层（crate / packages / wasm / SDK）先提交，上层（web / 调用方）后提交，保证每个提交都能独立构建。
- 同一功能的多处改动（实现 + 测试 + i18n + 必要文档）保持在同一提交，不按文件拆散。
- 纯格式化、临时文件、构建产物不要混进功能提交；临时文件放 `.tmp/`，不提交。

## 提交前自检

- 前端改动跑 `pnpm lint` 与相关测试；Rust 改动跑 `cargo check`。
- `git diff --cached` 只包含本次提交该有的文件，不夹带无关改动。

## 示例

单一变更：

```text
fix(QQAvatar): 更换 QQ 头像地址

旧头像接口不可用，改用 q.qlogo.cn 的 nk 参数接口。
```

多个变更项：

```text
feat(afk-animation): 添加缺失动画资源包的提示与下载链接

- 新增游戏资源包下载链接配置
- 新增多语言提示文本
- 新增资源包缺失状态判断逻辑
- 修复推荐构筑按更新时间倒序排列
```

重构 + 行为调整（用列表分清口径）：

```text
fix(walnut,raid): 批次最高档结算口径与默认赛季跟版本门限

- walnut：单轮期望改按“每批 3 张只结算最高档”建模
- raid：赛季号换算版本号，默认赛季取版本门限内最新
- CharAttrShow：神智回复并入数值分支
```

# 在线地图 → MapTool 坐标换算

`packages/data/d/onlinemapcache.data.ts` 文件尾的换算表：把同文件快照里各楼层底图上的
像素坐标（`site.x / site.y`）换算成 MapTool 世界坐标（UE 单位，100 单位 = 1 米）的逐地图参数表。

## 模型

- 相似变换：`world = s · R(θ) · online + t`（镜像不可能出现，模型里没有这一项）。
- **θ 只取正交整数角 {0, 90, 180, 270}**，s 恒为正（θ 与 θ+180 在 s 变号时等价，
  拟合后统一规范；vitest 里锁了这个不变量）。
- 同地图各楼层共用一套参数（多楼层联合拟合残差收敛，已验证）。
- 规律（非强制，先验只用它定性，不定量）：`θ = -region.mapRotation`；
  缩放按图聚类（~15 / ~30 / ~60 三档，太虚陵 map15 是 ~25.7 的例外）。

## 取样与标定（程序与数据都在 `tools/update-map-cache.ts`）

- 主取样：在线「传送点」matter ↔ MapTool `T_Gp_Trans*` 点位（16 张图逐张核对过数量，全部 1:1）。
- 锚点表 `TRANSFORM_ANCHORS`：人工核对过的共识点对（在线 site id ↔ 世界传送点名），
  含钓鱼点/灵鸟回声/梦魇残声/Leave 引导点等语义外点；同名多点用 `worldOccurrence` 区分。
- 拟合 `fitCardinalTransform`：枚举 4 正交角 × 镜像，固定旋转下最小二乘解 (s, tx, ty)，
  取残差最小。正交约束顺带把 2 点图的配对歧义变成了可验证的残差（map8/map15 由此确证）。
- 门禁：残差 >10 米直接抛错中断（错配对的残差都是 50 米起）；锚点 id 缺失/世界点改名
  也抛错。任何失败都不落地半份标定。
- 运行：`bun tools/update-map-cache.ts` 重拉快照时一并重算换算表；
  改完锚点后离线刷新用 `--transforms-only`；只校验用 `--check`（拟合已提交快照并逐字比对）。

## 置信度与坑

- `high`：≥3 对过约束拟合，残差一般 1~4 米（在线标点手标噪声，约数像素）。
- `medium`：2 对拟合（map8 废矿、map15 太虚陵）。
- `low`：仅 map9 盖雷亚剧院——全图只有 1 个传送点共识，旋转取 0、
  缩放借同组均值（`SINGLE_ANCHOR_FALLBACK_SCALE`），锚点处精确、离锚点越远越不准；
  补一个共识点即可重标。
- map14 曾被自动配准配反（自由拟合下 2 点无残差可辨），是靠第 3 个语义点纠正的：
  不要把自由拟合的 2 点配对当真理，正交约束 + 语义外点才是证据。
- map15 太虚陵 `θ=0`，不服从 `-mapRotation`（其在线底图方向本就不同）：不同地图参数
  就是可能不同，不要跨图硬套旋转。
- 快照是手标的，重拉后若个别标点漂移，`--check` 与回归测试会按图报错，先看是线上改了点
  还是锚点要跟进。
